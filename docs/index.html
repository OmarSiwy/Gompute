GPU kernels,
in Zig.

Write the kernel in Zig. The build compiles it to PTX and HSACO and embeds both in your executable; a thin runtime loads the driver and launches it by name; g.math gives the same bits on the CPU and the GPU.

Zig 0.18-dev CUDA / PTX HIP / HSACO

Define once

// src/kernels.zig
const g = @import("gompute");

pub fn scaleRelu(x: f32, scale: f32) f32 {
    return @max(x * scale, 0);
}

fn kernel(data: g.GlobalPtr(f32), len: u64, scale: f32) callconv(g.kernel_callconv) void {
    const i = g.globalIdX(256);
    if (i < len) data[i] = scaleRelu(data[i], scale);
}

comptime { if (g.is_device) g.exportRaw("scale_relu", &kernel); }

Launch it

if (comptime g.available(.cuda)) {
    var k = try g.RawKernel("scale_relu", .cuda).init(0);
    defer k.deinit();
    // alloc, upload, k.launch(grid, block, 0, args), download
}

On the CPU, call scaleRelu in a plain loop: Zig 0.18's loop vectorizer does the rest.

What you get

One source, two compilations

Your kernel file is compiled once for the host and once per GPU target, and the artifacts are embedded in the executable. A kernel name that is not in any root is a compile error.

Device-safe math

g.math gives you exp, log, sin, tanh and friends on NVPTX and AMDGCN, where the builtins simply do not compile.

The device primitives

Thread indices, warp shuffles that work on wave32 and wave64, barriers and device-scope atomics, plus streams, graphs, events and peer copies.

Install

zig fetch --save git+https://github.com/OmarSiwy/Gompute.git

Linux, Windows, macOS and wasm. The CUDA and HIP backends need linkSystemLibrary("c", .{}) on your executable, because the drivers are dlopen'd, and without libc Zig cannot resolve symbols out of them.
